# MCP-сервер

MCP-сервер даёт агенту VS Code или Cursor доступ к командам расширения 1C: Platform Tools: тесты, профили запуска, сборка и загрузка конфигурации и расширений, работа с базой. Агент вызывает ровно те же команды, что вы нажимаете кнопками. Сервер живёт отдельным расширением **1C: Platform Tools MCP**.

## Установка

1. Установите **1C: Platform Tools**: [Marketplace](https://marketplace.visualstudio.com/items?itemName=yellow-hammer.1c-platform-tools), [Open VSX](https://open-vsx.org/extension/yellow-hammer/1c-platform-tools).
2. Установите **1C: Platform Tools MCP**: [Marketplace](https://marketplace.visualstudio.com/items?itemName=yellow-hammer.mcp-1c-platform-tools), [Open VSX](https://open-vsx.org/extension/yellow-hammer/mcp-1c-platform-tools).
3. Откройте проект 1С: папку с `packagedef`.

## Подключение

**VS Code.** Ничего дополнительно не нужно.

**Cursor.** В палитре команд или в дереве **Инструменты 1С** → **Навыки для AI** выполните **Настроить MCP для Cursor**. Перезагрузите окно и включите сервер `mcp-1c-platform-tools` в настройках MCP: новый сервер Cursor добавляет выключенным.

После обновления расширения путь к серверу в этом файле обновляется сам. Путь, который вы прописали сами, не меняется.

### Настройка вручную

Если конфиг заводится без расширения, укажите путь к серверу. Запускайте его из папки проекта.

```json
{
  "mcpServers": {
    "mcp-1c-platform-tools": {
      "command": "node",
      "args": ["<каталог расширения>/out/src/index.js"]
    }
  }
}
```

Каталог расширения: `%USERPROFILE%\.cursor\extensions\yellow-hammer.mcp-1c-platform-tools-<версия>-universal` (Windows) или `~/.cursor/extensions/...` (macOS, Linux).

## Claude Code

Claude Code работает с проектом через открытое окно VS Code или Cursor:

1. Один раз запишите `.mcp.json` проекта, как в разделе [Настройка вручную](#настройка-вручную).
2. Откройте проект в VS Code или Cursor. Агент может сделать это сам: `code <путь>` или `cursor <путь>`.
3. Запустите Claude Code в папке проекта: сервер найдёт окно этой папки, и агент вызывает команды без настройки связи.

Если Claude Code запущен раньше, чем открыто окно, команд ещё нет. Когда окно загрузится, повторите просьбу.

## Несколько окон

Агент выполняет команды в том окне, из которого вы его запустили.

- Проект другого окна это окно не выполняет и называет то окно. Продолжайте там.
- Агенту вне окон окно выбирается по `projectPath`. Проект не открыт ни в одном окне: откройте его в VS Code или Cursor.
- Папка, открытая в двух окнах, не выполняется: оставьте её в одном окне.
- Папке, которой вы не доверяете, агент команды не выполняет. Подтвердите доверие и повторите вызов.

## Проекты окна

Попросите агента показать проекты окна или сделать другой текущим. Один вызов в другом проекте этого же окна текущий проект не переключает. В окне из нескольких папок годится проект из любой папки.

## Проверка

Напишите агенту «покажи состояние окружения 1С». В ответе будут активный профиль запуска, версия платформы и путь к базе. Дальше можно просить прогон тестов, переключение профиля, сборку конфигурации.

## Как агент работает с командами

- **Агент дожидается результата.** Инструменты возвращают код возврата и вывод команды, у прогонов тестов ещё и счётчики из отчёта. С параметром `wait: false` команда уходит в терминал, и ход выполнения видно на экране.
- **Окна не открываются.** Команда, вызванная агентом, никогда не показывает окна выбора: если данных не хватает, возвращается ошибка с подсказкой, какие параметры передать. Интерактивные мастера (поставка, установка версии, создание профиля) агенту недоступны, их выполняет пользователь.
- **Профиль и окружение.** `env_status` показывает активный профиль, файл настроек, строку подключения, выбранное окружение и имена его переменных; `env_selectProfile` и `env_selectEnvironment` переключают профиль и окружение по имени. Разовый прогон под другим файлом настроек задаётся параметром `settingsFile`: активный профиль при этом не меняется, а параметры вызова имеют приоритет над временными параметрами профиля.
- **Ошибки видны как ошибки.** Упавшие тесты, ошибки синтаксического контроля, ненулевой код возврата и обрыв связи с расширением помечают ответ как неуспешный. Синтаксический контроль отдаёт список ошибок с путём к файлу модуля. Длинный вывод обрезается до хвоста, целиком он остаётся в панели расширения.
- **Исходный код находится сам.** Каталоги исходного кода инструменты не принимают: конфигурацию, расширения, внешние обработки и отчёты расширение находит в проекте, в выгрузке конфигуратора и в проектах 1С:EDT.

## Автоматизация из агента

Агенту доступна команда `pipelines_run` с параметром `pipeline`: идентификатор или название цепочки из `.1cpt/pipelines.json`. `profile` и `environment` задают профиль и окружение на этот прогон вместо выбранных в редакторе; шаги со своими в пайплайне их сохраняют. Возвращается пошаговый отчёт: что выполнено, что упало, сколько попыток.

Редакторы пайплайнов и хуков агенту не публикуются: файлы он правит напрямую, состав полей подсказывают схемы `pipelines.schema.json` и `hooks.schema.json`. Шаг с подтверждением в таком запуске завершается ошибкой: подтверждать некому.
